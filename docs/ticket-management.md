# 打标管理

管理端侧栏的「打标管理」提供独立的 Turn-State 探测面板，路径 `/tickets`。
只有管理员会话或管理 API Key 可以访问对应接口。

## 配置

初次运行总开关与「业务请求使用有效票」均关闭，所有账号默认关闭打标。
填写专用打标代理池（每行一个 HTTP/HTTPS/SOCKS5 代理），选择账号模式后保存策略。手动探测按轮换顺序使用可用入口，自动探测按入口配额并发；自动探测与普通业务分别使用
专用代理和账号原有出口；专用代理不可用时不会回退直连。

代理池最多 64 个，已有条目的 URL 留空保留认证。自动探测间隔为 10–86400 秒，
手动探测间隔为 0–86400 秒，默认 0（上一请求结束后可再次点击）。
两者按账号共享最近探测时间，但分别计算等待期限；修改间隔后立即按新值计算。
手动 0 秒在网络失败后可立即重试，仍遵守 429、401/403 退避和单请求并发限制。
网络失败后的 60 秒退避仅用于自动任务。
代理池显示名称、脱敏地址和认证是否保存；修改名称时保留认证。支持单条添加、移除、
批量追加，以及从 RS 代理管理导入（服务端复制认证，浏览器不读取密码）。导入是快照，
以后修改原代理需重新导入。完整 URL 输入留空时按条目 ID 和策略 revision 保留原值。

代理条目支持启用/禁用和 1–3 并发设置，旧条目默认启用、并发 1。禁用不删除地址、认证或名称；
所有入口禁用时不发探测。`启用打标代理池` 可暂停整池，仍保留符合规则的已有票供业务复用。
暂停或修改设置不强制中断已经发出的请求；旧策略的迟到结果不会重新写入有效票。
并发按代理入口（协议、主机、端口）计算，相同入口的重复条目共用最低并发限制，不代表动态代理
背后的实际出口 IP。整个进程最多同时 12 个探测，超过上限按入口轮换。

| 账号模式 | 后台探测 | 手动按钮 | 有效票注入 |
| --- | --- | --- | --- |
| 关闭打标 | 不运行 | 不可用 | 不注入 |
| 仅手动 | 不运行 | 单次探测 | 总开关及注入开关开启时可用 |
| 自动打标 | 缺票或临近到期时探测 | 单次探测 | 总开关及注入开关开启时可用 |

默认长度规则为 Plus/Pro 292、Business/Team 332、其他套餐 292。
每个账号可以设置独立长度覆盖套餐默认值；合法范围为 64–4096。
这些是管理员选择的匹配规则，不是上游官方套餐协议，也不证明模型能力或质量。
只有 HTTP 200、目标长度匹配且票符合 `gAAAAA` 前缀及可传输字符要求时才采纳。

目标模型为精确名称，最多八个。默认 `gpt-6-astra` 和 `gpt-5.6-sol`。
有效期默认一小时，上限一小时；默认提前十分钟刷新。
账号最小探测间隔默认 60 秒。后台每轮挑选一个最久未探测的账号/模型，按启用入口的并发配额探测，
本轮结束后等待十秒，再按账号冷却期检查。手动按钮每次仍只发送一个请求，并与后台共用入口配额。
后台由 Host 监督，使用本进程调度，不等待 Redis 跨实例任务租约；仍只支持单进程、单副本。
页面显示后台最近检查时间；磁盘、数据库或上游响应慢时周期会延后，自动间隔不是精确的发包频率。

HTTP 429 遵循 Retry-After，至少退避一分钟；401/403 退避十五分钟，
网络错误退避一分钟。手动按钮也遵守退避与并发限制。
普通请求不会现场打票，无可用票时按原链路继续转发，不暂停账号或模型。
现有客户端的正常会话状态透传不因关闭打标而被清除。

策略修改需要保存，使用 revision 防止两个管理页面互相覆盖。切换手动/自动、修改间隔或
代理池会保留仍符合规则的有效票；关闭打标、移除模型或改变目标长度使不再适用的票失效。
缩短有效期会收紧已有票的期限，延长配置不会延长旧票。正在探测的旧策略结果不会写回。代理池文本框留空保留现有代理，清除代理
需关闭打标并勾选清除选项。配置接口只返回代理数量，日志返回去除认证的代理地址，不返回密码。

## 探测日志

面板保留最近 1000 条已执行探测记录，按新到旧显示；成功、未命中、限流和网络失败均记录。
包含账号、模型、触发方式、脱敏代理地址、HTTP 状态、实际/目标长度、耗时、退避时间和结果原因。
支持搜索、按命中结果筛选和分页，并汇总保留记录内各代理的命中次数及比例。
日志随私有状态文件持久化，保存策略不清空历史。历史版本没有记录的尝试无法补回。
并发占用或冷却期内拒绝的点击没有实际发出探测，不算探测记录；进程中止的在途请求可能没有完成记录。
不保存票原文、代理用户名密码、令牌或上游正文。代理地址是连接入口，不能当作动态代理的实际出口 IP；真实出口未经该请求关联确认时不显示为已确认。

## 存储与隔离

### 从 3.10.0-ticket 升级到 3.11.0-ticket

本 fork 的旧版本基于上游未发布的 main，已经执行独立的 `0016_client_request_profiles.sql`
和 `0017_model_pricing.sql`。继续保留这些迁移及其原始校验和，使用新增 `0018` 删除全局 Fast 字段；
不要替换成上游正式版合并后的 `0016`，也不要修改 `_sqlx_migrations` 绕过校验。
本迁移链适用于本 fork 的旧实例和空库，不可直接用于已执行上游正式版 3.11 迁移的数据库。

若开启了全局 Fast 禁用，先在旧版将需要限制的分组设为「关闭」，为未分组密钥配置合适的分组，
核实账号可用范围后关闭全局开关。新迁移在全局开关仍开启时会拒绝升级，避免限制静默失效。

升级前停止应用，备份 PostgreSQL、Redis、部署配置和完整运行数据目录。先在隔离环境验证恢复与迁移，
再替换 fork 的镜像。升级后管理员重新登录；检查打标配置、代理池及探测历史。回退需要恢复升级前
数据库和运行数据，并使用对应旧镜像，不能仅将新数据库交给旧二进制。

配置和有效票保存在 `host.runtime_data_dir/turn-state-tickets.json`，独立于数据库。
Linux 上新文件权限为 0600。文件包含代理认证和票材料，应按凭据保护，随运行目录
备份；普通 PostgreSQL 备份不包含该文件。Windows 部署需限制运行目录 ACL。
文件使用同目录临时文件及原子替换，写盘失败时不发布新内存配置。写盘在阻塞任务中执行，
不占用异步工作线程；请求取消后仍保持写盘、内存发布和后续修改的顺序。

新票按账号 ID、OAuth 认证材料摘要和上游模型隔离；Cookie 更新不使票失效。
旧票没有摘要时仅在原凭据 revision 一致时兼容使用。账号关闭、真实认证材料变更、票过期或目标
长度不匹配时不能注入；探测结束后重新核验账号和策略，避免旧结果覆盖新状态。
删除账号后其策略从页面投影中移除，后续保存完成清理。
最近探测摘要与未到期的错误退避从保留日志恢复；有效票、日志与策略重启后保留。

所有探测复用 RS 当前已核验客户端画像及证书验证路径，使用 HTTP/1.1 和每次独立
连接，读取响应头后关闭连接。探测请求采用 Sub2API 0.2.6 的最小 ping/pong 方式，
实现为 Rust Provider 模块，未复制或运行所附 Windows 可执行文件。
后台任务由 RS Host 统一管理关闭与取消。此功能沿用 RS 单进程、单副本部署约束。

参考实现提交：
[Sub2API 0.2.6 打票逻辑](https://github.com/Wei-Shaw/sub2api/blob/49a39b6dc1abed30fd227611e8af1108bc427610/backend/internal/service/openai_codex_ticket.go)。
该逻辑是第三方实现；票长度并非 OpenAI 公开质量指标。

## 管理接口

- `GET /api/admin/tickets`：设置 revision、非敏感策略、OAuth 账号、各模型最近结果、到期与退避时间。
- `POST /api/admin/tickets`：提交 `{revision, settings, proxies?, proxyUrl?, proxyPool?}`。代理字段只选一个，省略保留，空池清除。`proxies` 条目为 `{id?, name, url?, savedProxyId?, enabled?, concurrency?}`，已有条目省略 URL 保留认证，导入使用 `savedProxyId`；省略 enabled/concurrency 保留旧条目值，新条目默认为 true/1，并发只接受 1–3。`settings.manualIntervalSeconds` 省略时为 0，`settings.proxyPoolEnabled` 省略时为 true。
- `POST /api/admin/tickets/probe`：提交 `{accountId, model}`，单次探测并返回状态摘要。

响应沿用 RS `{code, message, data}` 信封。探测匹配与否是 `data.matched`，不是管理接口
自身 HTTP 状态。冲突或冷却返回 409，不合法策略返回 400；响应包含 `Cache-Control: no-store`。
票原文、Access Token、Refresh Token 均不进入页面响应或普通日志。
