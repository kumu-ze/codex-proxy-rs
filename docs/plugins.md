# 外部进程插件（实验）

插件用于在独立原生进程中提供管理页面、后台业务和受限请求扩展，减少业务扩展对宿主源码的耦合。接口仍在实验阶段，不应据此宣称任意第三方代码可以安全运行。

- [接口参考](plugin-api.md)：manifest、HTTP API、JSON-RPC、Provider回调与页面桥。
- [开发指南](plugin-development.md)：构建、打包、调试与验证。
- [参考插件](../examples/plugins/README.md)：最小Echo、独立快捷对话和Turn-State业务插件。

## 安装与管理

在管理员“插件”页面粘贴HTTP/HTTPS tar.gz插件包直链，可指定保存的下载代理和整包SHA256。仓库主页和源码ZIP不能直接安装；仓库链接用于展示来源和检查更新。

安装仅登记文件并校验，默认停用。确认来源可信后启用；提供menuLabel的插件出现在侧栏。页面仍在不透明来源iframe中，不具有宿主同源权限。作者和仓库来自manifest声明，不能替代发布者签名。

停用会关闭新调用入口、终止进程并释放回调服务；业务数据保留。卸载要求先停用，只删除宿主管理的程序目录，默认保留数据。已启用但故障的请求扩展拒绝请求，不能静默绕过保护；显式停用则不执行其请求逻辑。

“检查更新”读取声明的GitHub仓库Release并比较SemVer，显示发布页与安装链接，预发行明确标识；不会自动替换程序。升级先备份数据，再停用/卸载/安装新包。

本地安装命令仍可用：`codex-proxy-rs plugin-install <包目录> <安装目录>`。CLI不覆盖已有版本，也不会自动启用。

## 配置与持久化

首次没有注册表时导入可选YAML配置，路径相对配置文件：

```yaml
plugins:
  - directory: ../plugins/example-1.0.0
    data_directory: ../plugin-data/example
```

之后以 `<host.runtime_data_dir>/plugins/registry.json` 为唯一状态来源，避免删掉/停用的插件重启后被旧YAML重新启用。URL安装的程序在packages/<id>-<version>，数据在data/<id>。注册表通过临时文件和原子替换保存。最多16个插件，不支持多进程共享同一注册表。

程序与数据目录不能重叠或相互嵌套，插件之间的数据目录也必须独立。YAML导入的外部目录不会被卸载删除；改用URL重新安装会使用宿主管理的数据目录，迁移旧数据需管理员停用后自行复制并保留权限。

若旧版本程序目录残留但未登记，且完整清单、文件摘要一致、没有额外文件，则可恢复登记；不同、损坏或带额外文件的目录会明确报冲突，不自动覆盖。普通错误会清理临时目录，断电遗留仍需管理员处理。

## 职责与调用

组合根连接Host注册表、Admin端口和Provider。API只调用PluginOperations；Host负责安装/进程/持久化；Core定义RequestExtension与ExtensionServices端口；Provider拥有账号认证、固定探测和出站字段校验。

stdin/stdout承担有界JSON-RPC。provider.openai另提供每插件令牌保护的回环HTTP能力，OAuth由Provider保留。request.openai在实际账号选定、客户端身份清理后执行。ui.chat只授权宿主管理页面按已选Key代发同源/v1请求，密钥明文不发给插件。

具体函数、字段、限制与错误见接口参考；架构约束见[系统架构](architecture.md)。

## 信任边界与已知限制

原生插件拥有RS系统用户权限，可访问该用户的文件并自行联网；env_clear、摘要校验和iframe不能替代OS沙箱。SHA256只校验内容，不认证发布者。只安装可信代码。

provider.openai是宽权限，可读账号快照并解析含认证的代理地址；ui.chat可使用管理员可见的启用Key发起有用量请求。目前没有逐账号/逐Key授权、签名信任链、CPU/内存/cgroup限额或恶意子孙进程清理。

下载允许局域网地址，仅管理员可操作；显式HTTP CONNECT/SOCKS代理参与最终目的地解析，本地预检不是完整SSRF隔离。下载不继承宿主代理环境，不携带管理员Cookie。

管理与数据面共用每插件通信锁，管理操作可能导致500ms数据面等待超时；多个请求扩展串行执行，时延累加。后台探测应使用独立服务桥，不能长期占用管理RPC。

控制面操作串行，但没有跨文件事务、目录fsync或断电恢复日志；停止只能尽力取消在途请求。管理成功写结构化日志，尚无包含管理员身份的完整数据库审计。没有自动拉起故障进程或原地升级。

框架不新增数据库迁移；合并历史定制fork前需核对其迁移链，不能改写已有校验和。部署与升级前备份程序、注册表和业务数据。生产压力、长期稳定性及各OS/CPU组合需要各自验收。
